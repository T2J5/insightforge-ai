# Task 11：公开产品体验阶段总结

## 目标

Task 11 把前十个阶段形成的后端能力，变成招聘方无需阅读源码就能理解和操作的产品体验。页面不是静态作品集截图，而是直接连接项目现有 API 的真实客户端。

```text
首页创建调研
  → POST /api/runs
  → 跳转运行页
  → GET /api/runs/:runId 恢复权威状态
  → EventSource /events 接收增量事件
  → 完成后进入报告页
  → GET /api/reports/:reportId
  → 点击引用核对 Evidence
```

## 首页与创建表单

首页首先说明产品解决的问题：把问题规划、公开网页检索、证据提取、报告写作和引用评审编排为可观察的 Agent 工作流。创建表单提供企业名称、关注方向和快速调研模式，并显示游客额度和模型成本会被记录。

表单不伪造当前后端不支持的能力。文档上传 API 需要已有 `runId`，而创建任务会立即写入初始文档集合并入队；如果先创建再上传，Worker 可能已经开始执行。因此页面保留禁用入口并说明原因。后续若要开放，需要增加“预上传会话”，或把入队动作延迟到文档关联完成之后。

## 运行页：REST 与 SSE 各自负责什么

`GET /api/runs/:runId` 是权威快照，负责首次打开和刷新恢复。SSE 负责连接建立后的增量变化。两者不能互相替代：只有 SSE 时刷新会丢失已有状态，只有轮询时实时性和连接成本较差。

客户端用事件 ID 去重并按 ID 排序，终态到达后主动关闭 EventSource。短暂断线只显示自动重连提示，不把网络抖动误报为任务失败。取消按钮只在 queued/running 等可取消状态出现，取消成功后立即切换到 cancelled。

当前 Worker 只发布 starting、planning、completed 和 failure 等已有进度。页面不会虚构 researcher、writer 等节点已经执行；若希望时间线逐节点展示，需要在后续阶段由 Worker 或 Graph 节点发布更细的真实事件。

## 报告与证据抽屉

报告页展示执行摘要、固定章节、质量摘要和版本信息。Markdown 只解析项目需要的少量安全语法并生成 React 节点，没有使用 `dangerouslySetInnerHTML`，因此模型文本不能注入任意 HTML。

事实块旁的引用编号来自服务端返回的 Evidence UUID。点击后，原生 `dialog` 展示来源类型、来源类别、发布方、发布日期、原始 URL 和逐字引文。外部链接使用 `noopener noreferrer`，并在新标签页打开。

质量摘要只展示真实可计算字段，例如报告版本、事实块数和引用数。当前公开响应没有完整评测指标，因此页面明确提示其不等同于 Task 9 的离线质量分数，没有编造支持率或准确率。

## 运行时数据校验

TypeScript 类型只在编译期存在，无法保证线上 API 真正返回相同结构。浏览器 API 客户端使用 Zod 校验创建结果、运行摘要、SSE 事件和公开报告。响应不符合契约时，页面显示稳定错误信息，而不是让错误数据进入组件并在更深处崩溃。

## 响应式与无障碍

- 页面根节点使用 `overflow-x: clip`，并自动检查 320、375、414、768px 宽度；
- 所有主要按钮至少 44px，高频移动端控件提升到 48px；
- 表单具有 label、帮助文本、错误关联、禁用状态和即时焦点环；
- 页面提供跳到主要内容链接，导航支持 `Cmd/Ctrl + K`；
- 运行状态使用 `aria-live`，加载态使用 `aria-busy`；
- 引用与导航使用原生 dialog，并支持 Escape 和焦点管理；
- 动画在 `prefers-reduced-motion` 下关闭或缩短。

## 测试覆盖

组件测试覆盖事件去重、状态标签、加载、取消和完成报告入口。Playwright 在桌面 Chromium 与移动 Chromium 上验证：

1. 游客创建快速调研并观察 SSE 进度；
2. 完成后阅读报告并打开引用原文；
3. 刷新运行页后从服务端恢复完成状态；
4. 取消仍在运行的任务；
5. 四个关键移动端宽度没有横向滚动。

最终浏览器检查确认首页有有效内容、没有 Next.js 错误覆盖层、没有控制台错误，并在 375px 与桌面宽度下完成视觉检查。
