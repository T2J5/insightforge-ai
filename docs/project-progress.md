### 任务 4 验收结果

- Agent Graph 使用确定性条件边控制引用修订、质量修订和最终发布，避免模型自行决定无限循环。
- quick/deep 调研分别限制搜索次数、Token、预估成本和总时长，模型与搜索操作具有独立超时上限。
- 每个 Agent 节点执行前检查取消状态，researcher 在每次外部搜索之间重新检查取消状态。
- LangGraph 使用独立的 `langgraph` PostgreSQL Schema 保存节点状态和 pending writes，并以 ResearchRun ID 作为 `thread_id`。
- Worker 重试会读取最新 StateSnapshot；未完成 Graph 使用 `null` 输入恢复，已完成 Graph 直接提交业务结果。
- Checkpoint 恢复前校验 Run 身份，损坏或串用的 Checkpoint 使用不可重试错误终止。
- 恢复测试证明 researcher 临时失败后可以从已提交 checkpoint 继续，且不会重复执行 planner。
- 全仓格式化、lint、类型检查通过；41 个测试文件、355 项测试通过。
- 详细总结见 `docs/task-4-checkpointed-agent-summary.md`。

### 任务 6 当前验收结果

- 上传入口校验扩展名、MIME、魔数、20 MB 上限和每 Run 十个文档上限。
- PDF、DOCX、Markdown 和 TXT 统一解析为带页码与标题路径的结构化文档；空白或扫描 PDF 不生成索引。
- 分块目标 800 Token、最大 1,200 Token、重叠 120 Token，并保留页码和标题元数据。
- 文档按 `owner_id + content_hash` 幂等复用，通过 `run_documents` 关联到多个调研 Run。
- 摄取只在全部 Embedding 成功后事务写入 chunk 并标记 ready；失败文档不可搜索且保存公开错误码。
- PostgreSQL 全文检索与 pgvector 余弦检索均强制 owner 和文档过滤，经 RRF 融合并确定性重排。
- Agent 文档搜索工具的 ownerId 只能来自认证上下文，模型参数无法覆盖。
- 本地文件系统和 S3/R2 对象存储使用同一端口，可按环境配置切换。
- 全仓 format、lint、typecheck 通过；55 个测试文件、429 项测试通过。

### 任务 7 验收结果

- Writer 只读取 EvidenceRepository 返回的当前 Run、当前 owner 的正式 Evidence UUID。
- 报告使用固定章节和 fact/inference/summary 内容块，事实引用覆盖率门槛为 95%。
- 程序先检查引用存在性、身份、URL、章节和覆盖率，模型再判断引文语义支持度。
- 所有引用或质量问题共享一次修订额度；严重问题持续存在时禁止发布。
- 草稿与发布结果写入不可变 report_versions，确定性版本 ID 支持 Checkpoint 重放幂等。
- 匿名公开 API 只返回已发布报告和网页引用白名单；包含私有文档引用时拒绝公开。
- 详细实现和学习说明见 `docs/task-7-reviewed-cited-reports-summary.md`。
